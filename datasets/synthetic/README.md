# Synthetic corpus v1

This corpus contains 144 distinct permutations: 24 pilot and 120 main inputs.
There are 12 parameter cells: one uniform and three semi-random cells at each
of n=1024,4096,16384. Semi-random k values are 4,64,1024. Each cell has two pilot
inputs and ten main inputs. All generated bytes and construction traces are
saved in [v1](v1/manifest.json).

Python's MT19937 stream is initialized once with seed **42**. Generation order,
Python version, parameters and SHA-256 checksums are recorded in the manifest.
Pilot/main checksum sets are disjoint. A uniform shuffle samples permutations;
a semi-random input starts at identity and applies k nontrivial reversals sampled
by two distinct endpoints. k is not the optimum distance.

To recreate the candidate corpus into a new empty directory:

```bash
python3 scripts/generate_inputs.py --out data/recreated-synthetic \
  --sizes 1024 4096 16384 --k 4 64 1024 --instances 10 --pilot-instances 2
python3 scripts/validate_corpus.py --manifest data/recreated-synthetic/manifest.json
```

The saved manifest records the actual generating Python version. Reproduction
on another version must compare input checksums; a matching numeric seed alone
is insufficient evidence. Use the committed inputs for all measured variants.
[VALIDATION.json](VALIDATION.json) records integrity and construction-trace replay
checks. Three measured repetitions and one warm-up per implementation would
produce 1,440 sorting calls on the full main grid; E0 must confirm this and all
other stages fit the single 24-48 hour reservation.
